# キーマップ可視化 デザインルール v0.1

## 1. 目的

ZMK/QMKなどの複雑なキーマップを、1枚の図で直感的に把握できるようにする。

複数レイヤー、Hold-Tap、Tap Dance、Comboなどの機能を、物理キーの配置を維持しながら統合して表現する。

## 2. 基本方針

- 物理キーの配置を忠実に再現する。
- 各レイヤーを別々に描画せず、1セットの物理キーに情報を集約する。
- レイヤー番号は表示せず、意味のある名前を使用する。
- レイヤー名と色はキーマップごとに任意に設定できる。
- 同じレイヤーには一貫して同じ色を使用する。
- 複数OSに対応する場合は、いずれか1つを基準として描画し、他のOSとの差分は注釈にまとめる。
- 不要な装飾やプレースホルダーは表示しない。
- 実際のキーマップ設定に忠実であることを優先する。
- 同一キーボード図内では、すべてのキーの表示サイズと縦横比を統一する。
- キー内外の情報が重ならないよう、必要な表示領域を確保する。

## 3. レイヤーの表現

### 3.1 色と名前

- レイヤーごとに固有の色と表示名を設定する。
- 基本入力は黒系の文字で表示する。
- 追加レイヤーの出力は、対応するレイヤー色の文字で表示する。
- レイヤー名をラベルとして表示する場合は、対応するレイヤー色の背景に白抜き文字を使用する。
- レイヤー出力の文字には原則として背景色を付けない。
- レイヤー色は任意に設定できるが、同一キーマップ内では一貫して使用する。
- 各レイヤーの色は互いに十分区別できるものを選ぶ。
- 白背景上の文字と色付き背景の白抜き文字について、十分なコントラストを確保する。
- 具体的なカラーコードは規定しない。

#### 推奨配色例

| 表示スロット | 推奨色 |
|---|---|
| 追加レイヤー1 | 青 |
| 追加レイヤー2 | 緑・青緑 |
| 追加レイヤー3 | 紫 |
| 追加レイヤー4 | オレンジ |

この配色は一例であり、キーマップの用途や表示環境に応じて変更できる。

通常Hold、Combo、注釈などの共通要素には、レイヤー色と区別できる中立色を使用する。

### 3.2 キー内部の配置

基本入力はキーの中央に配置し、追加レイヤーの出力はキー上部の2行×2列に配置する。

| 位置 | 表示内容 |
|---|---|
| 中央 | 基本レイヤーの入力 |
| 左上・上段 | 追加レイヤー1 |
| 右上・上段 | 追加レイヤー2 |
| 左上・下段 | 追加レイヤー3 |
| 右上・下段 | 追加レイヤー4 |
| 下部 | Hold・Tap Danceなどの操作表示 |

- 基本レイヤーの文字は大きく表示する。
- 追加レイヤーの文字は、対応するレイヤー色で表示する。
- 各追加レイヤーをどの表示スロットに割り当てるかは、キーマップごとに任意に設定する。
- 表示スロットはZMK/QMKのレイヤー番号に固定対応しない。
- 追加レイヤーは上記の順序で表示位置を使用する。
- 表示する内容がない領域は空白にする。
- 各情報が重ならないように配置する。
- OSごとの差異は追加レイヤーの表示数に含めない。
- 必要な表示領域は第10章に従って確保する。

## 4. Hold-Tapと操作記号の表現

キー内部の下部は操作表示専用の領域とし、**記号のない機能名・ラベルはHold操作**を意味する。Holdを示す専用記号は付けず、Tap Danceなどの複数回タップだけに回数記号を付ける。

### 4.1 操作記号

| 操作 | 記号 |
|---|---|
| Hold | なし（下部の無印表示） |
| ダブルタップ | 真円2つ |
| トリプルタップ | 真円3つ |
| その他の複数回タップ | 回数に応じた真円 |

- 回数記号は機能名の直前に配置する。
- 記号と機能名は一体の表示要素として扱う。
- 記号の大きさや間隔は視認性に合わせて調整する。
- 操作表示領域以外の無印テキスト（Baseや追加レイヤーの出力）はHoldを意味しない。

### 4.2 通常Hold

- キー内部の下部に表示する。
- 機能名の前には操作記号を付けない。
- グレー系の文字を使用する。
- 背景色は付けない。
- Shift、Ctrl、Alt、GUIなどの修飾キーもこの方式で表示する。

### 4.3 レイヤー切り替え

- キー内部の下部に切り替え先レイヤーの名前を表示する。
- Holdによる切り替えの場合は、操作記号を付けず、下部にある無印ラベルとして表す。
- 背景は遷移先レイヤーの色とする。
- 文字は白抜きとする。
- Tap Danceなど別の操作で切り替える場合は、その操作の回数記号をラベル内の機能名の前に付ける。
- ラベルは角丸長方形とする。

### 4.4 Holdなし

- Holdの表示は行わない。
- ダミー文字や記号は表示しない。

### 4.5 追加レイヤー内のHold-Tap

- キー内部の追加レイヤー表示にはTap動作のみ表示する。
- Hold動作は注釈にまとめる。

### 4.6 複数操作の共存

- 同じキーにHold、Tap Danceなど複数の操作がある場合は、すべて表示する。
- 操作表示はキー内部の下部に縦に並べる。
- Holdは無印の機能名、Tap Danceは回数記号と機能名を一体として配置する。
- 表示行数に応じて必要な高さを確保する。
- 右下の注釈タグやほかの表示要素と重ならないようにする。

## 5. 枠線に重なるラベルの共通スタイル

枠線に重なるComboラベルなどには共通のスタイルを適用する。

- ラベルの幅・高さは文字または識別子の大きさと内側の余白に応じて決める。
- キー寸法に対する固定の幅・高さの割合は設けない。
- 同じ種類のラベルでは、高さや余白の印象を統一する。
- 角丸の形状・大きさの印象を統一する。
- 枠線に重なる量を統一する。
- 白抜き文字のサイズ感や太さをできるだけ揃える。
- ラベルの色は各機能の表示ルールに従う。
- ラベル内の文字は1行とする。
- 長い場合は短縮表記を使い、必要な情報を注釈に移す。

## 6. Comboの表現

Comboはレイヤーの識別色とは独立した表現とする。

- 背景色はダークグレー系とする。
- 文字は白抜きとする。
- ラベルは角丸長方形とする。
- 機能名は1行で表示し、改行しない。
- ラベルの幅・高さは内容と余白から決定する。キー幅・キー高さに対する固定比率は使用しない。

### 6.1 隣接する2キーのCombo

2つのキーの境界上に、Comboの機能名を表示する。

| 項目 | ルール |
|---|---|
| 幅・高さ | 文字サイズと内側の余白から決定 |
| 横位置 | 2キーの共有境界を中心 |
| 縦位置 | 基本入力文字の中心に揃える |
| 形状 | 角丸長方形 |
| 背景 | ダークグレー系 |
| 文字 | 白抜き・中央揃え・1行 |

- 第5章の共通スタイルを適用する。
- 角丸半径や文字サイズは個別に数値で固定しない。
- 基本入力文字の視認性をできるだけ損なわないようにする。
- 機能名が長い場合は短縮表記を使用し、詳細を注釈に記載する。
- キー境界をまたぐ部分も衝突判定の対象とする。

### 6.2 非隣接Combo

各キーの右枠線上に、1文字の識別子を表示する。

| 項目 | ルール |
|---|---|
| 幅・高さ | 1文字識別子と内側の余白から決定 |
| 横位置 | マーカーの中心をキーの右枠線に合わせる |
| 縦位置 | 基本入力文字の中心に揃える |
| 形状 | 角丸長方形 |
| 背景 | ダークグレー系 |
| 文字 | 白抜きの1文字識別子 |

- 同じComboに属するキーには同じ識別子を付ける。
- Comboの組み合わせと実行する機能は別欄にまとめる。
- 識別子のサイズは読みやすさと、隣接キーへの干渉を考慮して決める。

### 6.3 3キー以上のCombo

- 隣接・非隣接にかかわらず、識別子方式を使用する。
- 各キーに同じ識別子を付ける。
- 詳細は別欄にまとめる。

### 6.4 複数Comboへの所属

- 1つのキーが複数Comboに属する場合は、識別子を右枠線上に縦に並べる。
- 識別子同士が重ならないようにする。
- 必要な高さと周辺余白を寸法計算に含める。

### 6.5 レイヤー限定Combo

- 特定レイヤーでのみ有効なComboには、有効レイヤー名を併記する。
- 併記する場合もラベルは1行とする。
- 表示が長くなる場合は短縮表記を使い、詳細を注釈にまとめる。

## 7. Tap Danceの表現

### 7.1 基本表現

- Tap Danceはキー内部の下部に表示する。
- 機能名の前に、タップ回数に対応する真円を並べる。
- 通常のTap Danceはグレー系の文字と記号を使用する。
- レイヤー切り替えを行う場合は、第4章のレイヤー切り替え表示ルールを適用する。

### 7.2 複数回のタップ

- 2回タップは真円2つ、3回タップは真円3つで表現する。
- それぞれの回数で異なる機能を実行する場合は、操作ごとに表示する。
- 複数の操作表示は縦に並べる。
- すべての機能をキー内部に配置できない場合は、短縮表記と注釈を利用する。

### 7.3 Holdとの共存

Tap DanceとHoldが同じキーに設定されている場合も、両方表示する。

- Hold：無印の機能名
- Tap Dance：タップ回数分の真円＋機能名
- 2つ以上の操作表示はキー内部の下部に縦に並べる。
- 表示に必要な領域を第10章のルールで確保する。

## 8. 注釈の表現

OS差分や特殊な動作など、キー内部に収まらない情報は注釈として扱う。

### 8.1 注釈マーカー

- キーの右下隅に三角形のコーナータグを配置する。
- タグはグレー系の背景とする。
- 白抜きの番号を表示する。
- 注釈の内容は別欄にまとめる。
- タグの形状・サイズ感・配置はキーマップ全体で統一する。

### 8.2 注釈の運用

- 1キーにつき注釈番号は1つとする。
- 同じキーに複数の説明が必要な場合は、1つの注釈に統合する。
- OS差分も通常の注釈として扱う。
- ComboやTap Danceの補足説明にも利用できる。
- 追加レイヤー内のHold-TapのHold動作の説明にも利用できる。

### 8.3 注釈一覧の完全性

- 注釈マーカーが1つでも存在する場合、対応する注釈一覧を同じ図に必ず描画する。
- すべての注釈番号に説明本文を設け、キー側の番号と注釈一覧の番号を正確に対応させる。
- 説明本文のない番号、参照元のない注釈項目を作らない。
- 1キーに複数の説明がある場合は、1つの番号の下にまとめる。
- 注釈一覧の表示領域は描画前に確保し、画像の端で切れたり省略されたりしないようにする。
- 注釈欄を収められない場合は、図全体のキャンバスサイズや注釈欄のレイアウトを調整する。注釈本文の省略で対処しない。

### 8.4 表示領域との関係

- 注釈タグの占有領域を必要寸法の計算に含める。
- キー下部に縦並びする操作表示と重ならないようにする。
- Comboラベル・識別子との重なりも回避する。

## 9. 特殊なキーの扱い

### 9.1 透過キー

- `&trans` は表示しない。
- 追加レイヤーの該当箇所は空白にする。

### 9.2 無効キー

- `&none` は表示しない。
- 該当箇所は空白にする。

### 9.3 基本レイヤーに割り当てがないキー

- 物理キーの枠は表示する。
- 割り当てのない表示領域は空白にする。

### 9.4 特殊キー・マクロと操作名

- Bluetooth、マウス操作、マクロなどの表記方法は固定しない。
- キーマップごとに適切な略称・文字・記号などを選択する。
- 複数キーの組み合わせやマクロは、可能な限りキーの組み合わせそのものではなく、実行される**操作の意味**を短いテキストで表示する。
- OSの標準動作やマクロ定義など、根拠から意味が明確に分かる場合のみ操作名に変換する。
- アプリ固有のショートカットやカスタマイズ可能な割り当てなど、意味が不明・複数解釈可能な場合は、ユーザーに質問して確認する。
- 確認できない操作について、推測した意味を確定情報として描画しない。
- 回答が得られない場合は元のキー操作を暫定的に表示し、意味が未確認であることを明示する。
- 操作名が長い場合は短縮表記と注釈を組み合わせる。

### 9.5 キー以外の入力デバイス

- トラックボール、エンコーダー、タッチパッドなどの表示方法はキーマップごとに自由に決める。

## 10. レイアウトと寸法

### 10.0 描画前の情報整理

描画に先立ち、キーマップの定義を解析して表示内容を確定する。

1. 物理キー配置、Base、追加レイヤー、Hold、Tap Dance、Combo、OS差異などを列挙する。
2. 組み合わせ操作やマクロの意味を確認し、表示用の操作名を決定する。意味が不明ならユーザーに確認する。
3. 各キーに必要な注釈を確定し、キーごとに統合して番号を採番する。
4. すべての注釈番号について説明本文を作成する。
5. キー内の表示要素・境界ラベル・注釈一覧・Combo一覧・凡例などを踏まえて必要寸法とキャンバス領域を計算する。
6. 表示内容と注釈の対応を検証してから描画する。

描画後にも、キー内の表示内容と注釈一覧に欠落がないことを確認する。

### 10.1 キーサイズの統一

- 同一キーボード図内のキーは、すべて同じ表示サイズと縦横比を使用する。
- キーに割り当てられた情報量によって、個別のキーサイズを変えてはならない。
- キーの相対的な配置と並びは、実際の物理配列を忠実に反映する。
- キーサイズと間隔の絶対値は固定せず、表示領域を確保できるよう調整する。
- 特定のキーに必要な領域が増えた場合は、全キー共通サイズの変更で対応する。

### 10.2 表示領域

キー内部は次の3領域で構成する。

| 領域 | 表示内容 |
|---|---|
| 上部 | 最大2行×2列の追加レイヤー |
| 中央 | 基本入力 |
| 下部 | Hold・Tap Danceなどの操作表示 |

周辺にはComboラベル・識別子・注釈タグを配置する。

- 各領域の必要な幅と高さを、実際に表示する情報から求める。
- 追加レイヤーの表示が3つ以上ある場合も、上部の必要領域を十分に確保する。
- 複数の操作表示がある場合は、行数に応じて下部の高さを確保する。
- OS差異はキー内部の追加レイヤー数に含めない。
- 表示領域の不足を、重なりや極端な文字縮小だけで解決してはならない。

### 10.3 共通キーサイズの決定

1. 各キーに必要な上部・中央・下部の表示領域を算出する。
2. Combo・注釈などの周辺要素に必要な領域と余白を算出する。
3. 全キーの中で、必要な幅・高さの最大値を求める。
4. 正方形を基本として全キー共通サイズを決定する。
5. 全キーに同じサイズを適用し、表示の重なりがないことを検証する。

必要な表示領域を満たせない場合は、全キー共通サイズ・キー間隔の調整を優先する。ラベルのサイズは文字と余白に基づくものとし、キーが大きくなったからといってラベルを一定比率で拡大しない。

### 10.4 キーの縦横比

- **キーは原則として正方形とする。**
- 表示領域が不足する場合は、まず全キー共通の正方形サイズを拡大して対応する。
- 正方形では表示効率が著しく悪くなる場合に限り、縦長を許容する。
- 縦長にする場合も、必要最小限の高さとし、過剰な余白を設けない。
- 縦横比の決定には、追加レイヤー、基本入力、操作表示、Combo、注釈の必要領域を考慮する。
- すべてのキーで同じ寸法・縦横比を使用する。
- キーごとに異なる縦横比を適用してはならない。

### 10.5 要素の干渉防止

- 上部・中央・下部の表示が互いに重ならないようにする。
- Comboラベルが基本入力や隣接キーの内容を隠さないようにする。
- 複数Comboの識別子同士が重ならないようにする。
- 注釈タグが操作表示と重ならないようにする。
- キー境界をまたぐラベルを考慮し、キー間隔にも必要な余白を確保する。
- 機能名が長い場合は、意味を保った短縮表記や注釈への分離を認める。
- 文字サイズとラベルの余白を優先し、表示内容に比例しない過剰な空白を作らない。

### 10.6 数値指定

- 文字サイズや角丸半径などは、原則として数値で固定しない。
- Comboラベルや識別子の幅・高さをキー寸法の一定割合として指定しない。
- 枠線に重なるラベルは、第5章の共通スタイルを適用する。
- 全体の視認性と一貫性を優先して寸法を調整する。

### 10.7 図全体の領域構成

図全体を次の領域に分け、描画前にそれぞれの必要サイズを見積もる。

| 領域 | 内容 | 表示条件 |
|---|---|---|
| キーマップ領域 | 物理キー、Base、追加レイヤー、Hold、Tap Dance、キー上のComboラベル・識別子、注釈タグ | 必須 |
| 注釈領域 | 注釈番号に対応する説明本文、OS差分、特殊動作の補足 | 注釈タグがある場合は必須 |
| 補助一覧領域 | 非隣接Combo・3キー以上のComboの対応表、キー内で完結しない補足情報、必要に応じた凡例 | 対象情報がある場合は必須 |
| ヘッダ・メタ情報領域 | キーボード名、基準OS、対象キーマップ、バージョン、必要に応じたレイヤー凡例 | 任意 |

- **Tap Danceは独立した全体領域に分けず、キーマップ領域の各キー内部に表示する。** 長い説明のみ注釈領域へ移す。
- 隣接Comboラベルと非隣接Combo識別子はキーマップ領域に表示する。非隣接Comboや3キー以上のComboの組み合わせと機能の説明は補助一覧領域に掲載する。
- 注釈領域と補助一覧領域は別の役割を持つ。注釈番号の説明をCombo一覧だけで代用しない。
- 基本配置は**上部にキーマップ領域、下部に注釈領域と補助一覧領域**とする。キャンバスの形状によっては横並びにしてもよい。
- 領域が不要な場合は空の枠やプレースホルダーを表示せず、省略する。
- 各領域の内容が欠けたり、画像端で切れたりしないよう、キャンバス全体の寸法を調整する。
- キーの寸法や配置を保つために、注釈・補助一覧を無理にキー内部へ押し込まない。

## 11. デザイン原則

1. **忠実性** — 実際のキーマップ設定と物理配置を正確に反映する。
2. **一覧性** — 1枚の図でキーの機能とレイヤー構造を理解できるようにする。
3. **一貫性** — 同じ意味の情報には同じ視覚表現を使う。
4. **視認性** — 基本入力を最も読みやすくし、追加情報は必要以上に目立たせない。
5. **簡潔性** — 不要な情報や装飾を避け、詳細は注釈に分離する。
6. **柔軟性** — キーボードやキーマップごとの違いを許容し、細部まで過剰に規定しない。
